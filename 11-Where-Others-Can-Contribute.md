# Where Others Can Contribute

![Distinct collaborators contributing through protected paths without taking control of the preserved core](assets/open-work-collaboration.png)

## Why outside review is useful

The work spans preservation, temporal data, language processing, argumentation,
human factors, literary structure, privacy, and verification. Outside review can
strengthen both individual components and the end-to-end preservation of context.

Outside review is most valuable when it tests explicit boundaries and identifies the
specific capability, evidence, or measurement that would improve them.

## Highest-priority technical questions

### Temporal relationship quality

- How should cross-deposit relationship candidates be evaluated without forcing a
  link?
- Which evidence is sufficient for reattribution or supersession?
- How should conflicting lenses remain useful without becoming one final score?
- Which graph operations preserve the exact backward-selected topology during
  forward reconstruction?

### Personal meaning without impersonation

- Which observable dimensions add useful context while remaining distinct from
  motive?
- How can longitudinal change be measured without constructing a timeless persona?
- How should unknown, contradictory, and low-confidence observations influence
  retrieval and collapse?
- What independent fixtures can detect when a system has invented a human reason?

### Product-specific assembly

- How should a manager select and order specialists from a capability registry?
- How can product profiles be calibrated without hardcoding one final set of ratios?
- What metrics distinguish a readable but empty document from a faithful and useful
  one?
- How can editorial candidates request bounded context without turning the corpus into
  one giant prompt?
- What is the minimum authorized payload an external specialist needs to add measured
  value while the maintained human record, meaning, provenance, and future
  reconstruction authority stay local?

### Semantic and editorial evaluation

- What labelled sets can measure support, conflict, equivalence, and direction?
- How should narrative reflection, analogy, humor, or emotional progression be
  evaluated for fidelity and audience appropriateness?
- Which measures predict human comprehension, retention, and willingness to continue
  reading?
- How should regression anchors span manuals, technical reports, reflective records,
  explanations, and other products?

### Sovereignty and governance

- How can informed authorization be represented as a scoped, revocable, testable
  object rather than a Boolean?
- Which re-identification tests are appropriate for public derivatives?
- How should affected-person authority interact with automated publication gates?
- What governance structure can preserve individual ownership while allowing shared
  research and reusable components?

## Useful contribution packages

A bounded contribution should identify:

- the problem and why the capability exists;
- source and rights boundaries;
- typed inputs, outputs, and failure semantics;
- prohibited authority and unsupported claims;
- computational and operational cost;
- executable fixtures and adversarial cases;
- comparison with existing cogs;
- rollback or removal path;
- what evidence would justify wider adoption.

Useful work may include a labelled evaluation set, a deterministic transform, a
specialist adapter, an independent verifier, a calibration study, a privacy threat
model, a public bibliography, or a careful critique of an architectural assumption.

## Contribution selection criteria

- explicit machinery rather than simulation of a missing component;
- measured value for any proposed model or infrastructure increase;
- integration with an accepted path, including typed inputs and outputs;
- blind evaluation whose expected answer remains outside the evaluated system;
- traceable reasoning, source use, and omissions in any proposed rewrite;
- representations that preserve the source context they are intended to serve.
- external services treated as replaceable, typed contributors rather than durable
  repositories of project knowledge.

## Near-term development sequence

The next productive cycle should keep the evidence boundary small enough to inspect:

1. strengthen relation-quality evaluation;
2. test cross-deposit temporal links and same-graph replay on small mixed cases;
3. compare several product-specific assembly profiles without regressing established
   ones;
4. measure which handoffs add value and which merely add cost;
5. improve public documentation incrementally under the sovereignty gate;
6. scale only after the smaller boundaries remain correct.
